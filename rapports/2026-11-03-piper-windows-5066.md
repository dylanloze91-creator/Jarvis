# Piper Windows — binaire installateur et lecture « Écouter » (5066)

Date : 2026-11-03. Branche : `cursor/piper-windows-5066`. Agent : Cursor (Linux). Version de référence : **5.0.65**. **Non fusionné, non publié.**

## Résumé

Deux bogues Windows Piper corrigés :

1. **Binaire absent de l’installateur** — `setup-piper.mjs` téléchargeait le binaire de la plateforme du *build* (Linux en CI), pas Windows. `package:win` force désormais `JARVIS_PIPER_TARGET=win-x64`, avec contrôle `piper.exe`, DLL et `espeak-ng-data` dans `release.sh`, `after-pack.cjs` et `verify-piper-windows-bundle.mjs`.
2. **« Écouter » silencieux / erreur média** — la CSP du renderer n’autorisait pas `blob:` pour `media-src` (repli sur `default-src`). Les WAV Piper lus via `URL.createObjectURL` étaient bloqués → *Failed to load because no supported source was found*. Ajout de `media-src 'self' blob: jarvis-oww:`, helper `piperWavPlayback.ts` (journal `[piper] WAV reçu : N octets`, blob sûr après IPC).

Licences et voix ONNX inchangées (Siwis + UPMC, pas de Tom).

## Cause réelle du bogue 2

**Politique de sécurité du contenu (CSP)** : sans directive `media-src` incluant `blob:`, Chromium applique `default-src 'self' jarvis-oww:` aux éléments `<audio>` ; les URL `blob:` générées pour les WAV Piper sont refusées. Le binaire CLI fonctionnait car il n’utilise pas le renderer.
