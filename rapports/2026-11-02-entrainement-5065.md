### Points 4 et 5 — marge du verdict, totaux non comparables

- **Ce qui n'allait pas** : « meilleur » dès +1 réussite sur 87, donc dans le bruit d'un passage à l'autre ; et une mission écartée pour un seul des deux modèles donnait des totaux sur des missions différentes, comparés quand même.
- **Ce qui change** (`labCompare.ts`, `COMPARE_RULE = { maxLost: 2, minGain: 3 }`) : « meilleur » seulement si le total du candidat dépasse celui de la base d'**au moins 3** sur 87 **et** si sa moyenne par passage dépasse le **meilleur passage de la base** ; sinon « pareil » (« moins bon » sous −3). Si une mission est écartée pour un seul modèle, ou si le nombre de passages diffère : **« sans verdict »**, raison écrite (« totaux non comparables … examen à refaire, garder la base »), `incomparable: [ids]` dans le JSON, le script conseille de relancer l'examen.
- **Tests** : `labCompare.test.ts` — +2 → pareil ; +3 avec moyenne au-dessus → meilleur ; +3 mais meilleur passage de la base égal → pareil ; −2 pareil, −3 moins bon ; exclusion des deux côtés → comparable ; d'un seul côté → sans verdict ; passages inégaux → sans verdict ; règle écrite dans le JSON.
- Commit `af962eb`.
