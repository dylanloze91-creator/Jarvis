## Points 4 et 5 de la revue (`docs/revues/2026-11-02-audit-ux-5064.md`) — commit `fef00ce`

**Point 4 — `apps/desktop/src/main/tools/platform/exec.ts` (`run`).** Avant : à l'expiration du délai, SIGTERM d'abord, puis une seconde plus tard `taskkill /T /F` ; sous Windows le SIGTERM tue déjà le parent (`cmd.exe`), donc `taskkill /T` ne retrouvait plus l'arborescence et le programme lancé continuait. Maintenant, sous Windows seulement : `taskkill /PID <pid> /T /F` part **en premier**, tant que le parent existe ; s'il échoue (code de sortie non nul, ou `taskkill` introuvable), repli sur le chemin d'avant : SIGTERM puis SIGKILL après `KILL_GRACE_MS` (1 s). Si `taskkill` dit « ok » mais que le processus est encore là une seconde plus tard, SIGKILL de sécurité (jamais pendu). **Hors Windows, rien ne change** (SIGTERM puis SIGKILL une seconde plus tard).

**Point 5 — `apps/desktop/src/main/tools/applications.ts` (`closeWindows`).** Avant : `WaitForExit(3000)` par processus l'un après l'autre, donc jusqu'à 3 s × N (Discord, Teams, Spotify, VS Code = 5 à 10 processus) au-delà des 15 s du script, et la réponse « aucun processus » à tort ; `HasExited` pouvait lever une erreur d'accès (processus administrateur) qui faisait échouer tout le script. Maintenant : **un seul délai partagé** pour toute l'opération (`CLOSE_WINDOWS_WAIT_MS` = 5 s : `$deadline` calculé une fois, boucle qui s'arrête dès que tous ont disparu ou quand le délai est écoulé), script borné à 5 + 10 s de marge, et un dépassement dit « a dépassé le délai (15 s) » au lieu de « aucun processus ». `Stop-Process` et `HasExited` sont dans un `try/catch` (`Test-Exited`) : un accès refusé est rapporté sur une ligne `DENIED=` et devient « Accès refusé pour « X » : ce programme tourne sans doute en administrateur », jamais une exception, jamais « fermé ». Le script est produit par `buildCloseWindowsScript` (exporté pour les tests), le nom reste entre apostrophes (`psQuote`).

**Tests** (processus et minuteries factices : `spawn` simulé, `vi.useFakeTimers`, aucun vrai `taskkill` ni PowerShell, tournent sous Linux) :

- `apps/desktop/src/main/tools/platform/exec.test.ts` (8 tests) : Windows, `taskkill` lancé avant tout signal et réussi → aucun `kill` ; `taskkill` code ≠ 0 → SIGTERM puis SIGKILL une seconde plus tard ; `taskkill` introuvable → même repli, sans SIGKILL si SIGTERM suffit ; `taskkill` « ok » sans fin du processus → SIGKILL de sécurité ; hors Windows, aucun `taskkill`, SIGTERM puis SIGKILL ; processus qui s'arrête sur SIGTERM non SIGKILLé ; commande finie à temps jamais tuée ; le test UTF-8/BOM d'avant inchangé. Vérifié : sans la correction, les 4 tests Windows échouent.
- `apps/desktop/src/main/tools/close-application.test.ts` (7 tests) : un seul PowerShell et un seul `$deadline` quel que soit le nombre de processus, pas de `WaitForExit` ; délai partagé dépassé dit comme tel ; `try/catch` autour de `Stop-Process` et `HasExited` dans le script (fermeture douce et forcée), plus de `SilentlyContinue` ; `DENIED=` rapporté sans exception et sans « fermé » ; fermés + encore ouverts + refusés dans la même réponse ; « introuvable » toujours « aucun processus » ; par l'outil `close_application` sous Windows simulé, nom jamais entre guillemets doubles.

Les tests existants (`windows-tools.test.ts`, dont `describeCloseResult`) passent sans modification.
