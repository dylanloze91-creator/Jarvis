# Revue de `cursor/robot-voix-5066` (Claude, 2 novembre 2026)

Verdict : **ne pas fusionner en l'état**. Périmètre propre (rien hors `robot/voix/`, `jarvis_rover` non modifié, aucun secret, installateur sans `curl | sh`, ZIP Vosk vérifié), mais deux défauts bloquants et un « stop » pas assez sûr.

## Bloquant

1. **Le suivi ne marche jamais** (`robot/voix/jarvis_robot_voix/contrat.py` ~74-75). Les en-têtes sont lus dans un `dict` sensible à la casse construit depuis `getheaders()` ; le pont du PC envoie `x-jarvis-continue` et `x-jarvis-transcript` en minuscules (`packages/core/src/speaker/speaker.ts` sur `cursor/enceinte-5064`). Résultat : `continuer` toujours faux, transcription toujours vide. Les tests passent parce que le faux PC écrit la casse exacte. Corriger : lecture insensible à la casse (`reponse.getheader(...)`) **et** faux PC des tests qui envoie des en-têtes en minuscules, comme le vrai.
2. **Tout tourne dans le rappel audio de PortAudio** (`__main__.py` ~59-62 → `boucle.pas`) : Vosk, requête au PC (jusqu'à 90 s), `sd.play()` + `sd.wait()`. Interdit par PortAudio/sounddevice ; pendant une requête ou une lecture, plus aucune trame n'est traitée (un « stop » est perdu) ; une exception (clé USB débranchée, modèle absent, WAV inattendu) coupe le flux sans arrêter le processus, donc systemd ne redémarre rien et le « stop » local meurt en silence. Corriger : le rappel met seulement les trames dans une file bornée ; un fil de travail traite la file ; un fil séparé, **toujours actif**, écoute le « stop » ; `try/except` global, chien de garde qui relance le flux, et sortie du processus (code ≠ 0) si le flux ne repart pas, pour que systemd redémarre.

## À corriger

3. **« Stop » local fragile** (`boucle.py` ~87/103, `arret.py:34`, `fin_parole.py:12`/`:17`). Vosk reçoit les 300 ms d'avant (fin de « Jarvis ») → `[unk] stop` est rejeté ; « stop stop » aussi. Avec les moteurs, le seuil fixe de fin de parole peut faire attendre 15 s. Corriger : reconnaissance continue par petites trames, ignorer `[unk]`, accepter les répétitions, déclencher sans attendre la fin de parole ; tests avec ces cas.
4. **Arrêt qui échoue en silence** (`boucle.py` ~112-119, `contrat.py` ~103-106, `__main__.py:24`). Un seul essai de 2 s, pas de signal ; jeton du robot vide accepté au démarrage. Corriger : 3 essais rapides, son d'alerte si échec, contrôle du jeton au démarrage ; et si la transcription renvoyée par le PC est un arrêt, appeler aussi `/api/stop`.
5. **Versions Python** (`requirements.txt` numpy 1.26.4, scipy 1.13.1 sans roue pour Python 3.13 ; `installer.sh:19` accepte ≥ 3.11). Raspberry Pi OS récent = Python 3.13 → compilation sur le Pi. Corriger : versions qui ont des roues aarch64 pour 3.11 à 3.13 (vérifier sur PyPI), ou limiter clairement la version de Python.
